# 실기체(G1)와의 관계 — 멘토·조교용

> **학생 안내용이 아닙니다.** 학생에게는 "실기체 제어는 멘토의 검증된 스택으로만
> 한다"까지만 전달합니다(교재 2.3 안전 수칙, 5장 도입부).

## 이 저장소가 실기체 코드를 포함하지 않는 이유

1. **안전.** 교육 1주차 학생이 수정 가능한 저장소에 실기체 구동 코드가 있으면,
   실수로 실기체에 연결되는 경로가 생깁니다. 시뮬레이터 전용으로 분리해
   그 경로 자체를 없앴습니다.
2. **교육 목표.** 이번 로테이션의 목표는 "지켜보고, 관찰 창구(토픽)와
   제어 창구(SDK)를 구분해 이해"하는 것입니다(교재 4·5장). 시뮬레이터로 충분히
   달성됩니다.

## 개념 매핑 (시뮬 ↔ 실기체)

| 이 저장소 | 실기체 스택 | 비고 |
|---|---|---|
| `LocoClient.Damp/StandUp/Move/StopMove/…` | unitree_sdk2(_python) high-level loco client | 함수 '모양'을 맞춘 교육용 설계. 실제 시그니처·지원 여부는 **펌웨어/SDK 버전에 따라 다르므로 반드시 실기체 스택에서 확인** |
| `GetMode()` / `GetLastError()` | FSM id / 에러 조회 | 실기체 모드 체계는 더 세분화되어 있음 |
| `/g1/lowstate` (g1_edu_interfaces) | DDS `rt/lowstate` (unitree_hg) | 교육용 축약 메시지. 배열 순서는 동일(아래) |
| 가상 행어(`hanger=True`) | 실기체 거치대 | 기립 절차 감각을 맞추기 위한 것 |
| 낙상 → 자동 damp + `FALL_DETECTED` | 실기체 보호 동작 | 개념만 대응 |

**관절 배열 순서는 실기체 DDS 29자유도 순서와 동일**하게 맞춰 두었습니다
(`docs/joint_map.md`, 근거: `docs/g1_joint_index_dds.md`). 학생이 시뮬에서 외운
인덱스가 실기체 관찰 때 그대로 통합니다.

## 실기체 세션 전 멘토 점검 항목

- [ ] 실기체 제어 PC의 SDK·펌웨어 버전 확인, 검증된 데모 스크립트만 사용
- [ ] 네트워크 인터페이스 이름(예: `eth0`)·로봇 IP 확인 — 교재 3.3의 "실행 인자"
      이야기는 실기체에서 이 값을 넣는 것을 말함 (시뮬레이터는 인자 불필요)
- [ ] `ROS_DOMAIN_ID` 분리 — 시뮬 실습 PC와 실기체 네트워크가 섞이지 않게
- [ ] 학생 노트북에서 실기체 네트워크 접속 금지(관찰은 멘토 PC 화면/프로젝터로)
- [ ] 시뮬과 실기체의 차이를 짚어줄 것: 접촉 마찰·지연·발바닥 형상·안전 영역,
      그리고 시뮬 보행기는 교육용 단순 제어기라는 점(실기체 내장 제어기와 무관)

## sim-to-real 관점 한 줄

이 시뮬레이터의 보행은 관찰·실험용 단순 제어기입니다. 실기체의 내장 보행
제어기와 성능·거동이 다르며, "명령 속도와 실측 속도가 다른" 현상(README 관찰
노트)은 그 차이를 토론하는 소재로 쓰도록 의도된 것입니다.
